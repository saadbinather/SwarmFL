# SwarmFL synthetic quickstart assets

This directory is a local, unpublished Hugging Face model-card candidate for the
small synthetic demonstration generated by `swarmfl-quickstart`. It is not a
clinical model, benchmark, medical device, or recommended checkpoint.

## Architecture and output

The demo creates three independent two-input NumPy linear probability adapters.
Each remains on its Flower client. A fixed routing policy chooses at most one peer
and `DynamicFusion(kind="mean")` combines the origin and actually observed selected
prediction. Output is a scalar probability for an artificial Bernoulli label.

Required identities are `linear-a`, `linear-b`, and `linear-c`; their ordered
inputs are `(x0,x1)`, `(x2,x3)`, and `(x4,x5)`. No normalization is applied.
The generated declaration records bind adapter IDs, schemas, and checkpoint hashes.

## Generate and load

```bash
pip install swarmfl==0.1.0a1
swarmfl-quickstart --output demo --feedback
python -c "import json; print(json.load(open('demo/result.json')))"
```

The compatible package version is `swarmfl==0.1.0a1`. Checkpoint provenance is
deterministic local generation from seed 8042; exact SHA-256 values are written to
`demo/declarations.json`. No checkpoint files are committed here because they are
generated, tiny, and meaningful only as a transport/API demonstration.

## Evaluation and limitations

There is no clinical or held-out performance claim. The demo verifies three real
CPU Flower nodes, external metadata registration, one-peer selected-only new-case
consultation, dynamic mean fusion, and version-pointer rollback. It does not train
shared parameters, prove routing superiority, provide secure aggregation or
differential privacy, or establish confidentiality. Synthetic inputs/predictions,
identifiers, logs, and shared updates can still disclose information.

Historical CDC checkpoints, CDC records, Qwen weights, private artifacts, and
rejected candidate models are intentionally excluded. Publish GitHub/PyPI first;
publish this card later only after license/ownership approval and after deciding
whether a generated demo asset provides enough standalone value.
